Incident Memory Agent — Project Spec
One-line pitch
An AI agent that remembers every past production incident — root causes, fixes, and outcomes — and uses that memory to diagnose new incidents, suggest fixes via GitHub, monitor live deployments, and generate documentation automatically.
Core Architecture
1.	LLM: Groq (openai/gpt-oss-120b or qwen/qwen3-32b) — unchanged, no fine-tuning
2.	Memory layer: Hindsight Cloud — stores structured incident records, retrieves similar past incidents
3.	Toy repo: a small app you own (Flask/Express) deployed to Vercel or Render, with a few intentionally buggy versions to demo against
4.	Tools: GitHub MCP (or API), Vercel/Render API
End-to-End Flow
1.	New incident reported (manually via UI, or auto-detected from deploy/monitoring API)
2.	Agent classifies the incident (service, severity, error type, signature) and writes structured record to Hindsight
3.	Agent retrieves similar past incidents from Hindsight memory, with similarity scores
4.	Agent reasons over retrieved memories + current incident → produces diagnosis
5.	Agent fetches relevant code via GitHub MCP based on past incident's resolution notes
6.	Agent proposes a fix (diff or draft PR) based on the pattern that worked before
7.	Agent generates outputs: postmortem doc, on-call brief, etc. (see Feature Modules below)
8.	Resolution gets written back to Hindsight, enriching memory for next time
Feature Modules (build in this priority order)
1. Core Memory Loop (MUST HAVE)
•	Ingest synthetic incidents (15-30) into Hindsight via simulated "conversations" with the LLM
•	New incident → retrieval → LLM diagnosis using retrieved context
•	UI shows: incident input, retrieved memories side-by-side, agent's diagnosis
•	This alone satisfies the 25% "Use of Hindsight Memory" criterion if done well
2. Auto-Classification on Ingest (CHEAP, HIGH VALUE)
•	On any new incident, agent extracts: service name, severity, error category, root cause type
•	Writes structured tags back to Hindsight (makes future retrieval better)
•	Demonstrates agent acting on its own memory, not just passive Q&A
3. GitHub MCP — Code-Aware Fix Suggestions (STAND-OUT FEATURE)
•	Connect to your own toy repo (full write/PR access)
•	Agent fetches the file referenced in a similar past incident's resolution
•	Proposes a diff or opens a draft PR with a suggested fix based on the past pattern
•	Frame: advisory only, human reviews/merges — intentional safety scoping
4. Vercel/Render Integration — Live Deploy Awareness (STRETCH)
•	Pick ONE platform (Vercel or Render) to keep auth simple
•	Agent polls deployment status/logs via API (trigger manually during demo, not 24/7 polling)
•	Correlates failed deploy with recent GitHub commit
•	Full loop: bad commit → deploy fails → agent detects → correlates with commit → checks memory → suggests fix referencing past pattern
5. Postmortem Auto-Generation (CHEAP, NO NEW INTEGRATIONS)
•	After an incident is "resolved," agent generates a structured postmortem doc: 
o	Summary: what happened, in plain language
o	Timeline: detection → diagnosis → fix → resolution
o	Root cause: pulled from agent's diagnosis
o	Impact: services/users affected (synthetic data)
o	Resolution steps: what was done
o	Similar past incidents: cross-references retrieved from Hindsight
o	Action items: e.g., "consider adding monitoring for X" — generated by LLM
•	This is pure text generation from existing memory + current incident — very low build cost, high "feels complete" payoff
6. On-Call Handoff Brief (CHEAP, NO NEW INTEGRATIONS)
•	On demand, agent generates a shift-handoff summary: 
o	Open/recent incidents and their current status
o	What's been tried so far (from memory)
o	What's still unresolved / needs attention
o	Suggested next steps based on similar past incidents
•	Demonstrates "memory → time saved for humans" directly
7. Trend/Pattern Detection (NICE TO HAVE)
•	Agent periodically scans incident memory and flags recurring patterns: 
o	"checkout-service has had 3 connection-pool incidents in 30 days — recommend systemic fix"
•	Strong "agent acting proactively" moment for the demo
Synthetic Data Plan
•	Generate 15-30 fake incidents across 4-6 services (e.g., checkout-service, auth-service, payments-api, search-service)
•	Deliberately create recurring patterns per service: 
o	checkout-service: connection pool exhaustion (recurs 3x)
o	auth-service: token expiry misconfiguration (recurs 2x)
o	payments-api: third-party timeout (recurs 2x)
•	Each incident record includes: timestamp, service, symptoms, error logs (realistic-looking), root cause, resolution steps, time-to-resolve, engineer who fixed it
•	Use the LLM itself to generate these realistic-sounding logs/postmortems
Demo Script (60-second story)
1.	"Here's our toy app, deployed on [Vercel/Render]. It's been running for weeks, accumulating incident history."
2.	Push a bad commit → deploy breaks (live)
3.	Agent detects the failure, classifies it, searches memory
4.	Agent shows: "This matches Incident #4 from 2 weeks ago — same service, same error signature (87% match). Root cause was X, fixed by Y."
5.	Agent fetches the relevant file via GitHub MCP, proposes a fix diff / opens draft PR
6.	Agent auto-generates a postmortem doc for this new incident, cross-referencing the past one
7.	(Bonus) Agent flags: "this is the 2nd time this pattern occurred — recommend a permanent fix"
Judging Criteria Alignment
Criteria	Weight	How this project hits it
Innovation	30%	Memory-driven code fixes + live deploy correlation — rare combo
Hindsight Memory	25%	Memory is visibly central: retrieval shown side-by-side, classification writes back, trend detection
Technical Implementation	20%	Multi-tool orchestration: LLM + Hindsight + GitHub MCP + deploy API
User Experience	15%	Clear before/after story, transparent retrieval, generated docs
Real-world Impact	10%	Postmortems, on-call briefs, fix suggestions — all things real SRE teams need
Build Order Recommendation
1.	Synthetic data generation script
2.	Hindsight ingestion + retrieval (core loop) — get this rock solid first
3.	Auto-classification on ingest
4.	Postmortem generator + on-call brief (cheap wins, do these once core works)
5.	GitHub MCP fix suggestions
6.	Vercel/Render integration (only if time remains)
7.	Trend detection (only if time remains)
Tech Stack Notes
•	No fine-tuning, no RL — base LLM + prompting + retrieved context only
•	Backend: Python or Node (your team's call)
•	All "real-time" integrations should work on-trigger during demo, not require 24/7 background polling
